LaTeX 项目题目提取与结构初始化工作流
1. 任务概述
本项目的工作流旨在自动化构建 LaTeX 目录结构。系统需要在指定的基础目录下新建一个项目文件夹，并从多个指定的源目录中提取特定格式的内容（仅限题目部分）和图片资源，重命名并汇总至这个新建的项目文件夹中，同时按照要求控制排版密度与垂直间距。
2. 核心参数
在执行任务时，必须先向用户确认以下四个参数：
BASE_DIR (基础目录)​：用户指定的父目录路径。
PROJECT_NAME (项目名称)​：将在 BASE_DIR 下创建的新文件夹的名称。
SOURCE_DIRS (源目录列表)​：包含原始扫描版 PDF 文件所在目录的路径数组或列表。
PROBLEMS_PER_PAGE (每页题数)​：指定生成的 LaTeX 章节文件中，每页排版的题目数量（用于自动插入分页符，如用户未回答则默认每页排版两道题）。
3. 执行步骤 (Workflow)
步骤一：初始化目标项目结构
访问并进入指定的 BASE_DIR。
在该目录下创建一个名为 PROJECT_NAME 的新文件夹，并将此文件夹设为当前工作根目录（Workspace）。
在工作根目录内，创建基础文件夹结构：
创建 chapters/ 目录。
创建 figures/ 目录。
在工作根目录内创建并初始化主文件 main.tex。

步骤二：批量读取与内容提取（OCR 版本）
现在的任务是处理扫描版 PDF（无文字层），请严格按照以下流程遍历并提取题目：
1. 文件扫描与预处理：
   遍历 SOURCE_DIRS 列表（或指定的 PDF 文件夹）。定位目标扫描版 PDF 文件。
   如果 PDF 没有文字层，请利用 Python 工具（如 PyMuPDF/fitz 或 pdf2image）将 PDF 的每一页渲染为图像（建议 200-300 DPI 以保证 OCR 准确率），暂存到临时目录。
2. OCR 精准识别：
   调用 OCR 工具（如 PaddleOCR、Tesseract，或直接调用多模态大模型 Vision API）对每页图片进行文字识别。
   将识别出的文本按页组装。
3. 精准提取题目：
   解析 OCR 识别出的文本。利用正则表达式或大模型语义理解，精准提取出仅包含“题目”的部分（如带有题号“1.”、“(1)”或“【例题】”等特征的问题描述）。
   忽略非题目类的正文、页眉页脚、页码等干扰内容。
4. 记录溯源信息（非常重要）：
   对于每一个提取出的题目，除了记录原文本，必须额外记录两个关键元数据：
   - `source_file`: 该题目来源于哪个 PDF 文件。
   - `page_number`: 该题目所在的 PDF 物理页码（从 1 开始计数）。
   （注意：由于是扫描版，没有原始图片切片，后续需要通过页码从原 PDF 中截图或直接利用刚才渲染的页面图片作为该题目的配图）。
5. 数据结构输出：
   最终请将提取结果整理成结构化数据（例如 JSON 或统一格式的 Markdown ），包含：题目文本、原始 PDF 路径、所在页码。以便后续生成 LaTeX 时能够正确关联图片。
（接续 OCR 提取任务）

步骤三：合并与生成章节文件及分页控制
针对步骤二中提取出的所有题目，根据其元数据（或内容特征）识别其所属的“章节名称”，并分类合并。
1. 在工作根目录的 chapters/ 目录下，以该章节名称创建对应的 .tex 文件（例如：chapter_name.tex）。
2. 将提取出的题目内容按照规范的 LaTeX 格式写入到对应的章节 .tex 文件中。在每写入一道题目后，必须紧接着自动插入 \vfill 命令，以确保题目在页面中垂直均匀分布。
3. 排版与分页控制：在写入题目内容时，系统需进行计数。每当连续写入的题目数量达到 PROBLEMS_PER_PAGE 的设定值时，必须在当前的 \vfill 之后自动插入 LaTeX 分页命令（\newpage 或 \clearpage），然后再继续写入下一题。

步骤四：基于 OCR 溯源信息的图片截取与关联（针对扫描版 PDF 的特殊处理）
注意：由于源文件是扫描版 PDF，没有现成的独立图片文件。我们需要通过之前记录的页码进行截图替代。
1. 图片截取：根据步骤二记录的每道题的 `page_number`，利用 PDF 处理工具（如 PyMuPDF）将原 PDF 的对应页面渲染/裁剪为图片。
   - 策略 A（整页截取）：直接将包含该题目的整页截取为图片。
   - 策略 B（区域裁剪）：如果 DSH 具备版面分析能力，尝试仅裁剪出该题目对应的区域（包含公式或图形）作为图片。
2. 重命名与防覆盖规则：将截取出的图片严格按照其最终在目标文件中对应的章节和题号进行全局重命名（例如：对应 1.1 题，重命名为 fig_1_1.png）。
3. 图片迁移：将重命名后的图片文件保存/迁移到工作根目录的 figures/ 文件夹中。
4. 引用插入：确保新生成的 .tex 章节文件中的图片引用路径（如 \includegraphics{figures/fig_1_1.png}）与重命名后的图片名称完全一致，并插入到对应题目的合适位置。

步骤五：生成 main.pdf 并推送到 GitHub 远程仓库
在所有做题本项目生成完成后，先在项目根目录使用 XeLaTeX 连续编译两次 main.tex（如执行两次 xelatex main.tex），最终生成的 PDF 必须命名为 main.pdf；确认编译无误后，再将整个 BASE_DIR 目录推送到远程 Git 仓库。
远程仓库地址为 https://github.com/dongjunfan5-star/Textbook-Workbook（SSH 方式：git@github.com:dongjunfan5-star/Textbook-Workbook.git）。
推送前确保 .gitignore 文件已正确配置，排除 LaTeX 构建的中间产物（.aux, .log, .out, .toc, .synctex.gz 等）；但最终产出的 main.pdf 是交付物，必须保留并提交，不得排除。
使用 git add -A 暂存所有新增和修改的文件。
使用 git commit 提交更改，提交信息应包含新增的做题本名称和题目数量统计。
使用 git push origin main 推送到远程仓库。
如果推送被拒绝（远程有新内容），先执行 git pull --rebase origin main 拉取并变基，解决冲突后再重新推送；不得直接使用 git push --force 覆盖远程历史，确需强制推送时必须先征得用户确认，并使用 git push --force-with-lease origin main。
4. 注意事项与约束
全局唯一性：不同源目录的题目序号如果出现重复，需向用户提示或自动重新编号，确保生成的图片名不会互相覆盖。
提取内容时，必须使用正则表达式或大模型语义理解确保“只获取题目部分”，不得混入无关段落。
所有生成的文件均需采用 UTF-8 编码。
Git 推送：每次完成做题本项目后，必须自动推送到 GitHub 远程仓库，确保代码同步。
